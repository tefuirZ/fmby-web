## B. 三条结构性结论（本表读出，**非设计描述**）
1. **7 个键 Free 即给**（local / scrape / compat.emby / alist / openlist / open_api / probe.remote）
   ⇒ 对它们「未授权⇒隐藏入口」是**错误口径**（会误伤免费基线）；它们缺 surface 位是**设计使然**，不是漏做。
2. **10 个键无 path 门**（表内 `❌`）：local / compat.emby / ms.account_pool / ms.load_balancing /
   alist / openlist / users.expiration / identity.google / poster_imghost / internal_imghost
   —— 其中 5 个属「Free 基线/建议豁免」，3 个属「provider 维度或未实现」，2 个属「需按 provider 细化」。
3. **唯一「挂了门但谁都拿不到」的键 = `feature.metadata.advanced_scrape`**（门 ✅ + 四套餐全缺）
   ⇒ 该端点对**任何**授权用户都 403。这已超出文案范畴，属**功能可用性缺陷**，须产品裁决。

## C. 与 15-surface 视角的关系（对账）
- surface（15）↔ 键（23）：差集 = **Free 基线的 7 键中的 3 个（local/scrape/compat.emby）**
  + **alist/openlist**（Free 给但无位）+ **open_api**（Free 给但无 surface）+ **ms.load_balancing**（未实现）
  ⇒ 这就是「23 − 15 = 8」的全部来源，逐条可解释，**不存在"神隐"的入口**。
