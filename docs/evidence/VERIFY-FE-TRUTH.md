# VERIFY-FE-TRUTH — 独立（非作者）验证「UI 不再撒谎」6 项（只读）

> 方法：起**独立真栈**（backend 19099 / web 19080 / 独立 mkdtemp 库；未碰 8080/8081/18091），
> admin/admin 登录后逐项**渲染取证**（`page.evaluate` innerText + 按钮态 + 网络 5xx 监听 + 驱动流程）。
> 只读、未改任何产品码。构建/测试前查 `/proc/loadavg`（起栈时约 27>8 稍等降至 ~8 再起）。

## 环境
- 栈：`node host/e2e/start.mjs`，`FMBY_E2E_BACKEND_PORT=19099 FMBY_E2E_WEB_PORT=19080`（二进制 `/data/fmby-build/local-target/debug/`）。19099/19080 均 `200`。
- 账号：e2e seed 的 `admin/admin`。
- 局限：e2e seed **不种 CAS 内容**（`/manage/site/cas/contents` 恒空列表）⇒ G2/G3/G4 的**条件态**（有行/截断/入队返回）无数据可渲染。

## 逐项：期望 / 实测渲染原文 / 判定

### G1 CAS 保存按钮点即 500 ⇒ 禁用/明确标注 — ✅ 通过（渲染+流程取证）
- 期望：写面不可用时**不点即 500**、不「假装成功」。
- 实测：盘配置表 `local · e2e-local` 行，`保存` 按钮初始 `disabled`（未 dirty）；填优先级 `99` 变 dirty ⇒ `保存` **enabled**；点击后网络监听 **`5xx = []`（无 500）**、无错误横幅。
- 判定：**旧「点即 500」缺陷已消**（写面接通或优雅处理，不再 500/不假装成功）。

### G5 「后端列表端点尚未接线」/ 真空列表 — ✅ 通过（渲染取证）
- 期望：页面**不出现**「尚未接线/数据面未就绪」；**真·空列表**显示「暂无数据」（两态分开）。
- 实测：`/manage/site/cas/contents` innerText 含 `暂无 CAS 内容`；**无** `尚未接线`/`未接线`/`数据面未就绪`（forbidden 三项均 false）。
- 判定：**通过**（unwired 话术已消，真空列表据实显示暂无数据）。

### 安装向导（#77）全页无「重启」 — ✅ 通过（渲染取证）
- 期望：同页不两段并存、凭据只一次、全页**无「重启」**（后端 `restart_required:false`）。
- 实测：`/install` 可达（本实例安装模式进程挂了 install 路由），innerText **不含「重启」**（forbidden=false）。（「同页不两段/凭据一次」需 apply 后中段态，默认已装实例不重跑向导，见下「未覆盖」。）
- 判定：**无「重启」字样通过**（与后端 restart_required:false 契约一致）。

### G2 `hasLocalEntity` 三态（未知/无/有，未知不得显示成"无"） — ⚠ 未渲染（缺数据，非失败）
- 期望：`未知（后端未接线）`/`无`/`有` 三态，**未知≠无**。
- 实测：`/manage/site/cas/contents` 为**空列表**（e2e seed 无 CAS 内容）⇒ 无数据行 ⇒ 三态不可见。
- 判定：**无法用默认 seed 渲染取证**（需先有 CAS 内容行）。forbidden（把未知渲染成"无"）未观测到（无行可观测）。建议：补一条种 1 条 CAS 内容的 e2e / 或用带 CAS 的库复跑。

### G3 截断提示 + 不得「共 N 条/已显示全部/还有 N 条」 — ⚠ 未渲染（缺数据，非失败）
- 期望：有**截断提示**；**不得**出现 `共 N 条`/`已显示全部`/`还有 N 条`（后端不返回 total）。
- 实测：空列表 ⇒ 无截断场景；**forbidden 三项（共N条/已显示全部/还有N条）均 false**（未编造 total）。
- 判定：**禁出现的假 total 串未出现（正向）**；截断提示本身需 >N 条 CAS 内容才能渲染，默认 seed 无法取证。

### G4 created=false→「幂等命中，未重复入队」/ pending→「转常规上传（非错误）」 — ⚠ 未渲染（需驱动入队流程，非失败）
- 期望：`created=false` 显「幂等命中，未重复入队」；`pending` 显「转常规上传（非错误）」（**不得标红**）。
- 实测：`/manage/site/cas/publish` 静态文案已见扇出区诚实态（「发起扇出写面待后端接线」+ 按钮禁用，不假装可用）；但 G4 的**条件态**（幂等/常规）需选中源内容并触发入队、后端返回 `created=false`/`pending` 才渲染——默认 seed 无 CAS 源内容可选，无法驱动到该态。
- 判定：**无法用默认 seed 渲染该条件态**（需 CAS 源内容 + 入队动作）。建议：补 e2e 驱动入队并断言两种返回态。

## 汇总
| 项 | 渲染取证 | 判定 |
|---|---|---|
| G1 保存点即 500 | ✅ 实测无 5xx | **通过** |
| G5 未接线话术/真空列表 | ✅ 无「尚未接线」+ 空显「暂无 CAS 内容」 | **通过** |
| 安装向导 无「重启」 | ✅ innerText 无「重启」 | **通过** |
| G2 hasLocalEntity 三态 | ⚠ 空列表无行 | 未覆盖（缺 CAS 内容） |
| G3 截断提示 | ⚠ 空列表 | 禁出假 total 未现（正向）；截断态未覆盖 |
| G4 幂等/常规上传 | ⚠ 无源内容可入队 | 未覆盖（缺 CAS 内容+流程） |

**结论**：可渲染取证的 3 项（G1/G5/安装向导「无重启」）**全部通过**；G2/G3/G4 因 e2e seed 不含 CAS 内容而**无法渲染到目标条件态**（**非失败**——禁出现的造假串「共N条/已显示全部/还有N条」「尚未接线」「重启」均未观测到）。建议主代理：补「种 CAS 内容 + 驱动入队」的 e2e 覆盖 G2/G3/G4 的条件态（只读验证侧已尽 default seed 所能）。
