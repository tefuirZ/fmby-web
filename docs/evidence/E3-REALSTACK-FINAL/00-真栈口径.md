## 过程中抓到的三个真问题（证据见各项文件）

1. **旧二进制嵌套线型会静默丢帧**：本机最初使用的 E3 二进制是扁平修复前的构建
   （hello/快照帧 payload 仍是 `{kind,data}` 嵌套）⇒ 前端 parseTaskCenterBatch 解不了批帧 ⇒ 计数恒 0。
   换农场扁平定案版后 hello 帧 payload 扁平（`{user_id,admin_scope,connected_at}`）⇒ 批帧可达。
   **结论：扁平定案二进制与 E3 前端必须配对验证**（这正是 T1 真栈 32 批全丢的同根因）。
2. **scan/identify 不推批**：task.center.batch 只由 `POST /api/manage/task-center/actions/batch`
   （Retry Failed 项）触发（农场同口径）——普通扫库/识别链路不产生批帧（如实记录）。
3. **全页错误分支在 SPA 与 API 同源形态下结构性不可达**：错误分支要求 `isError && !data`，
   而 SPA 与 API 同源 ⇒ 后端死 = SPA 首载也死；真实可达错误面 = **详情抽屉**（列表有缓存、详情查询无缓存）。
